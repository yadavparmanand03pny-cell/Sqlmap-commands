1. Clickjacking Kya Hai

Clickjacking (UI Redressing) ek attack hai jisme attacker victim ko trick karta hai kisi element pe click karne ke liye jo unhe actually dikh nahi raha hota. Attacker target website ko ek **invisible/transparent iframe** mein load karta hai aur apne khud ke fake page ke upar exactly overlay karta hai jaha victim ka click expected hota hai.

Victim ko lagta hai wo apni site pe kisi normal button (jaise "Play Video" ya "Claim Prize") pe click kar raha hai, lekin actually unka click **target site ke real, sensitive button** tak pahunch raha hota hai — bina unke consent ya knowledge ke.

2. Ye Kaise Kaam Karta Hai

1
Attacker apni malicious webpage banata hai jisme tempting content hota hai (game, prize, video)
2
Target website ko iframe mein embed karta hai: <iframe src="https://target.com/sensitive-action">
3
CSS se iframe ko invisible karta hai: opacity: 0.0001
4
Iframe ko exact position pe rakhta hai jaha victim ka decoy button dikh raha hota hai (z-index + absolute positioning)
5
Victim decoy button pe click karta hai → actually invisible iframe ke andar target site ka real button click ho jata hai

Visual Layer Concept

LayerKya hota haiVisibility
Top (z-index high)Invisible target site iframe (real button)Invisible (opacity ~0)
Bottom (z-index low)Attacker ka decoy content (fake button)Visible

3. Step-by-Step Testing Methodology

1
X-Frame-Options header check karo
Burp Suite mein target page ka response headers dekho: 
X-Frame-Options: DENY          → protected, framing blocked
X-Frame-Options: SAMEORIGIN    → protected, sirf same-origin framing allowed
(header missing)               → possibly vulnerable
2
CSP frame-ancestors check karo
Content-Security-Policy: frame-ancestors 'none';   → protected
Content-Security-Policy: frame-ancestors 'self';   → protected
(CSP header missing frame-ancestors directive)     → possibly vulnerable
3
Simple iframe test PoC banao — Section 7 se basic template lo aur target URL daalo
4
Local file save karke browser mein open karo aur dekho target page load hota hai ya blocked hota hai (blank/error)
5
Agar load ho jaye — sensitive action wale page pe test karo (settings change, delete account, follow/like, fund transfer)
6
Overlay/decoy design karo taaki actual click position target ke button se match kare — screenshot le ke measure karo
7
Impact demonstrate karo — PoC record/screenshot lo jisme dikhe ki decoy click se target action trigger hua

4. Advanced Variants Advanced

Double Clickjacking

Do clicks involve karta hai — pehla click ek benign action trigger karta hai jo page ko change kar deta hai, dusra click (jo victim expect nahi karta) sensitive action trigger karta hai. Modern browsers ke single-click protections ko bypass karne ke liye use hota hai.

Cursorjacking

CSS se custom cursor render karke actual cursor position ko visually offset kar diya jata hai — victim ko lagta hai wo kahi aur click kar raha hai jab ki real cursor kahi aur hota hai.

Drag-and-Drop Clickjacking

Click ki jagah drag-drop interaction abuse hoti hai — victim ko game/puzzle jaisa UI dikhaya jata hai, unka drag action actually target site ke form ko autofill/submit kar deta hai.

Likejacking

Social media "Like"/"Follow" buttons ko invisible overlay se click karwana — victim unknowingly content share/promote kar deta hai.

Filejacking

File upload/download dialogs ko invisible overlay ke through trigger karna, victim ke system se files access karne ke liye (browser-dependent, mostly legacy).

Nested Iframe Bypass

Kuch weak `SAMEORIGIN` implementations ko bypass karne ke liye multiple nested iframes use kiye jate hain jab framebusting script incomplete ho.

Report likhte waqt severity ko target ke specific sensitive action ke impact se justify karo — generic "clickjacking found" likhna weak hota hai, "clickjacking on delete-account endpoint leads to account deletion without consent" strong hota hai.

6. Defense / Prevention Developer Side

1
X-Frame-Options header set karo
X-Frame-Options: DENY
2
CSP frame-ancestors use karo (modern, more flexible)
Content-Security-Policy: frame-ancestors 'none';
3
SameSite cookies set karo taaki cross-origin requests mein session cookie na jaye
4
Sensitive actions ke liye re-authentication/confirmation maango (password re-enter, CAPTCHA)
5
Framebusting JS as fallback (legacy browsers ke liye, primary defense nahi honi chahiye)

Automated Detection Script (Python)

import requests

def check_clickjacking(url):
    r = requests.get(url)
    xfo = r.headers.get('X-Frame-Options')
    csp = r.headers.get('Content-Security-Policy')
    
    print(f"URL: {url}")
    print(f"X-Frame-Options: {xfo}")
    print(f"CSP: {csp}")
    
    if not xfo and (not csp or 'frame-ancestors' not in (csp or '')):
        print("[!] Possibly vulnerable to Clickjacking")
    else:
        print("[+] Protected")

check_clickjacking("https://target.com")
