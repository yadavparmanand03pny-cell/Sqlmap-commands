OSINT Day 1 — complete reference notes

Google Dorking Kya Hai

Google Dorking (ya "Google Hacking") ek OSINT technique hai jisme Google ke advanced search operators use karke aisi public information dhundhi jaati hai jo normally direct search se nahi milti — exposed files, login panels, misconfigured servers, leaked documents, etc.

Ye koi "hacking tool" nahi hai — Google khud ye search karta hai, tum sirf smart queries likhte ho. Data already public hai, bas usse structured tarike se find karna aata hai.
Important: Sirf apne authorized bug bounty targets ya khud ke systems par use karo. Kisi aur ki private/leaked info dhundna ya access karna illegal hai, chahe Google se hi kyun na mile.

Google Hacking Database (GHDB)

Ek public, categorized database jisme hazaaron ready-made dorks hain — vulnerable servers, sensitive files, login portals, error messages ke liye categorized. Exploit-DB ke saath maintained hota hai.
Kaise use karo:
1. GHDB search karo (publicly available, search engine se easily mil jaata hai)
2. Categories browse karo: "Files containing juicy info", "Vulnerable servers", "Login portals", etc.
3. Relevant dork copy karke apne target domain ke saath combine karo (site:target.com + wo dork)

Practical Workflow (Recon ke Liye)

Step 1: Target domain confirm karo (scope ke andar hi)
Step 2: Basic dorks se shuru karo — exposed directories, login panels
Step 3: File-based dorks try karo — PDF, XLSX, SQL, LOG, ENV files
Step 4: Subdomain discovery dork chalao, naye subdomains note karo
Step 5: Har result ko manually verify karo — Google index purana ho sakta hai, live check zaroori hai
Step 6: Jo bhi interesting mile, ek doc/spreadsheet mein log karo — future recon (subdomain tools, headers analyzer) ke liye input banega

Limitations & Cautions

Scope: Sirf authorized targets par use karo — Google se milne wali info bhi agar tum use exploit/access karte ho bina permission, wo illegal hai.
Freshness: Google ka index kabhi outdated hota hai — jo dork result dikh raha hai wo page ab exist na kare, ya content change ho chuka ho. Hamesha live verify karo.
Rate limits: Bahut zyada automated/rapid queries Google temporarily block kar sakta hai (CAPTCHA). Manual pace se karo.
False positives: Har "index of" ya "login" result vulnerability nahi hota — sirf ek starting point hai, deeper analysis zaroori hai.
